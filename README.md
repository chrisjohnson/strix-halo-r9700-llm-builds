# strix-halo-r9700-llm-builds

Model-engine build catalog, `modelctl`, and the benchmark orchestrator for
[`local-ai-machine`](https://github.com/chrisjohnson/local-ai-machine) — an AMD Ryzen AI
Max+ 395 ("Strix Halo", `gfx1151`) box with an r9700 eGPU dock, running LLMs across both
GPUs side by side (vLLM, llama.cpp, and Ollama) for coding-assistant use and cross-engine/
cross-model comparison.

>
> **→ [Interactive dashboard](https://chrisjohnson.github.io/strix-halo-r9700-llm-builds/)**

## What's here

- **`modelctl`** — the operational tool for bringing model builds up/down. Every build is
  its own standalone Docker Compose project (`builds/<id>/docker-compose.yaml`), never
  routed through a shared compose file — `modelctl` handles the `-p <project>` isolation,
  health-gated sequential bring-up, and exclusivity bookkeeping so nothing else has to.
  ```
  modelctl up [<build-id>...]
  modelctl up --standing <path-to-standing-list> [--exclusive]
  modelctl down [<build-id>...]
  modelctl logs [<build-id>...]
  modelctl list
  modelctl ps
  modelctl exec <build-id> [<cmd>...]
  ```
  `up` with no arguments and no `--standing` is an error — it never guesses which builds
  to start. `down`/`logs` with no arguments act on everything (`down`: every build
  directory; `logs`: every currently-running build container). `--standing` without
  `--exclusive` refuses to start anything if a build outside the standing list is already
  running, leaving the decision to the caller; `--exclusive` stops those first instead.
- **`builds/`** — one directory per verified model+engine combination (67+ today):
  `build.yaml` (identity, tuning history, measured results), `docker-compose.yaml` (the
  single-service compose file `modelctl` drives), `benchmarks/` (raw per-run JSON +
  stdout logs pushed here by `llm-inference-bench`). See `builds/README.md` for the full
  layout invariants, port allocation, and GPU-co-residency rules.
- **`llm-inference-bench/`** — the containerized benchmark orchestrator (a LAN-visible
  queue service, port 8092) that drives real benchmark runs against any build via
  `modelctl`, pushing raw results straight into `builds/<id>/benchmarks/`. Published as
  its own CI-built image; see `docs/benchmark-api.md` for the HTTP API.
- **`docker/`** — Dockerfiles for a few custom-built llama.cpp variants (DFlash2, Laguna
  fork w/ ROCm and Vulkan) that some `builds/` entries reference directly, outside the
  standard `kyuz0/amd-strix-halo-toolboxes`/`vllm-therock-gfx1151` images.
- **`scripts/`** — `generate_interactive_dashboard.py` (the dashboard above) plus a few
  one-off build/benchmark scripts for the custom-Dockerfile variants above.
- **`knowledge/`** — `decisions/` and `research/`: dated, sourced findings (hardware
  quirks, engine/backend comparisons, tuning investigations) that don't belong in a
  single build's own `build.yaml`.

## How this is consumed by `local-ai-machine`

This repo is vendored into `local-ai-machine` as a **read-only Nix flake input**
(`flake.nix` there) — `modelctl` itself is installed on the box's `PATH` as a thin
wrapper that always execs through the stable symlink
`configuration.nix`'s `linkComponentCompose` activation script maintains, so it's always
running whatever revision is currently pinned. Unlike the other three vendored
components, this one is **not** consumed via an `include:`d Docker Compose fragment —
there is no single shared compose file for models at all, by design (see `modelctl`'s own
header comment and `builds/README.md`'s "Layout invariants" for why).

Bumping the pin: `deploy.sh --update-input strix-halo-r9700-llm-builds` on
`local-ai-machine`, followed by a normal deploy switch.

**Credentials**: this repo has its own dedicated read-write Deploy Key, mounted into the
`llm-inference-bench` container only (`/home/chris/.secrets/strix-halo-r9700-llm-builds-
deploy-key` on the box) — separate from `local-ai-machine`'s own read-only checkout
credential and from the shared GitHub App the other three components use. Benchmark
results get committed and pushed straight to this repo's `main` from a dedicated
checkout (`/var/lib/git-checkouts/strix-halo-r9700-llm-builds`), never through the human
box checkout.
